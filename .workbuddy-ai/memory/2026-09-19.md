# 2026-09-19 (دور سوم — ادامه تا پایین صفحه)

## درخواست
«محصولات از پایین هم ادامه داشته باشن، از پایین صفحه جدا نباشن» — جدول باید تا
لبه پایین ویوپورت ادامه داشته باشد، نه اینکه وسط صفحه تمام شود.

## 🔴 تلاش اول شکست خورد (نکته مهم flex)
ابتدا `.stk-page` را `display:flex; flex-direction:column` کردم و
`min-height: calc(100vh - 48px)` دادم. **نتیجه برعکس شد:** چون `min-height`
فقط *حداقل* ارتفاع را تعیین می‌کند و سقفی نمی‌گذارد، کارت جدول تا اندازه محتوا
رشد کرد → ارتفاع کارت **۱۸٬۶۹۱px** و کل صفحه **۱۸٬۹۰۹px** شد و صفحه اسکرول‌بار
عمودی گرفت (دقیقاً چیزی که نمی‌خواستیم).

**درس:** برای قفل‌کردن ارتفاع باید `height` (نه `min-height`) بدهیم و زنجیره
flex را کامل ببندیم.

## ✅ راه‌حل نهایی
```css
.stk-page {
    display: flex; flex-direction: column;
    height: calc(100vh - 48px);   /* نه min-height */
    min-height: 420px;
}
.stk-page > .stk-table-card,
.stk-page > .stk-empty { flex: 1 1 auto; min-height: 0; }

.stk-table-card { display:flex; flex-direction:column; min-height:0; overflow:hidden; }
.stk-table-scroll { overflow:auto; flex: 1 1 0; min-height: 0; }   /* مهم: 1 1 0 */
```
- `height` به‌جای `min-height` → ارتفاع قفل می‌شود.
- **`min-height: 0` روی flex-item ها حیاتی است** — پیش‌فرض `min-height:auto`
  اجازه می‌دهد آیتم تا اندازه محتوا رشد کند و اسکرول داخلی از کار می‌افتد.
- `flex: 1 1 0` (basis صفر) روی اسکرولر تا فضای باقی‌مانده را بگیرد.
- `page-header` و `stk-toolbar` هر دو `flex-shrink: 0` گرفتند تا فشرده نشوند.
- عدد ۴۸px = padding عمودی `main-content` (`var(--space-6)` = ۲۴px بالا و پایین).

## نتیجه اندازه‌گیری‌شده (viewport = ۹۰۰px)
- `doc scrollH / clientH = 900 / 900` → **صفحه اسکرول عمودی ندارد**.
- کارت جدول: `top=169 bottom=852 h=683` → فاصله تا پایین ویوپورت فقط **۴۸px**
  (همان padding بالای/پایین مین‌کانتنت) — یعنی جدول تا پایین ادامه دارد.
- اسکرولر: `clientHeight=610` برای `scrollHeight=18619` → اسکرول داخلی کار می‌کند.
- `thead` → `position: sticky` فعال.
- حالت خالی هم درست است: `stk-empty` ارتفاع باقی‌مانده (۷۰۷px) را پر می‌کند و
  صفحه اسکرول نمی‌شود.
